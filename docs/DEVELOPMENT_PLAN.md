## 1. 프로젝트 개요

**한 줄 요약:** 팀장(사용자)가 한 줄로 지시하면, 가상 사무실에 있는 AI 직원들이 **실제 AI로** 업무를 나눠서 처리하고, 그 과정이 사무실 화면과 업무 로그에 실시간으로 보이며, 최종 결과는 **팀장가 승인해야 저장되는** 웹 앱.

**핵심 가치**
1. **보이는 협업** – 누가 무엇을 하는지 사무실 그림과 로그로 바로 보인다.
2. **실제 실행** – 흉내가 아니라 진짜 LLM 호출과 웹 검색으로 초안을 만든다.
3. **팀장 결재** – AI 결과물은 초안이다. 승인 전에는 확정·저장되지 않는다.
4. **비용 투명성** – 토큰, 검색 횟수, 예상 비용(원)을 실시간으로 보여준다.

| 직원 | 위치 | 담당업무 | 웹 검색 | 모델 등급 |
|---|---|---|---|---|
| 팀장 | 팀장실 | 사용자 본인. 지시·결재 | – | – |

| AI 컴플라이언스 담당 | 좌하 | **전자금융거래법·전자금융감독규정, 개인정보 보호법, 신용정보법**, 정보통신망법, ISMS-P 대응. 보안 정책·지침 문서, 감사·검사 대비 증적 목록 | ✅ (법령 개정 확인) | 보통 |
| AI 취약점 점검 담당 | 하단 중앙 | 시스템·웹·클라우드 점검 체크리스트, 전자금융기반시설 취약점 분석·평가 대응, 위험도 평가, 조치 계획·일정 관리 | – | 보통 |
| AI 침해대응 담당 | 우하 | 사고 대응 플레이북, 제공된 로그·알림 분석, 사고 보고서·경위서, 재발 방지 대책, 금융사고·정보 유출 시 신고·통지 절차 연계 | – | 보통 |

**업무 범위의 한계:** AI 직원은 직접 시스템에 접속하거나 명령을 실행하지 않습니다. 시스템 점검(포트 스캔)은 **팀장 승인을 받은 뒤 앱이 정해진 방식으로만** 실행합니다 (4.2.3 참고).
**민감정보:** 지시 내용은 Claude API로 전송되므로 실제 고객정보·비밀번호·내부 IP 등은 입력하지 않도록 입력창 아래에 안내합니다.

**담당자 배정 키워드 (시뮬레이션용, 3단계부터는 비서실장이 직접 판단)**
- 위협정보 분석가: 키워드와 상관없이 항상 먼저 참여
- 취약점 점검: 점검, 진단, 체크리스트, 조치, 위험도
- 침해대응: 사고, 침해, 대응, 로그, 유출, 경위서, 플레이북
- 컴플라이언스: ISMS, 개인정보, 신용정보, 전자금융, 법, 규정, 정책, 지침, 감사, 인증
- 보안교육: 교육, 훈련, 안내문, 공지, 뉴스레터, 피싱
- 해당 없음: 취약점 점검 + 침해대응

**직원 상태:** `대기` → `작업 중` → `검토 요청` → `완료` (+ `오류`)

## 3. 핵심 사용 흐름

```
팀장 지시 입력
   │
   ▼
AI 비서실장: 지시 분석 → 작업 계획(누구에게 무엇을) 수립
   │            └ 로그: "AI 비서실장 → AI 위협정보 분석가  위협 동향 조사 요청"
   ▼
담당 직원들 병렬/순차 실행
   │  - 위협정보 분석가: 웹 검색(검색 횟수 집계) → 요약 + 출처
   │  - 취약점 점검/침해대응/컴플라이언스/보안교육: 조사 결과를 받아 각자 초안 작성
   ▼
AI 비서실장: 결과 취합 → 최종 보고서 작성
   │
   ▼
결재 패널에 "팀장님 확인 필요" 등록
   │
   ├─ [승인] → 결과 저장(히스토리), 다운로드 가능
   └─ [반려 + 코멘트] → 비서실장이 수정 작업 재지시
```

**테스트용 시나리오** (화면에는 표시하지 않고 개발 검증에만 사용)
- "최근 랜섬웨어 대응 준비 상태 점검해줘": 위협 동향 조사 → 점검 체크리스트 → 대응 플레이북 → 임직원 안내문
- "고객 신용정보 유출 사고 경위서 써줘": 유사 사고 사례 조사 → 경위서 초안 → 신용정보법·개인정보 보호법상 신고·통지 의무 검토
- "전자금융감독규정 개정 내용 정리하고 임직원 공지 만들어줘": 개정 사항 검색·검토 → 임직원 공지문

## 4. 기술 설계

### 4.1 기술 스택 (권장)

| 구분 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js (App Router) + TypeScript** | 화면과 서버 API를 한 프로젝트에서 처리 |
| 스타일 | Tailwind CSS | 레이아웃의 베이지·크림 톤, 카드 UI 빠르게 구현 |
| 사무실 그림 | **SVG + CSS 애니메이션** (React 컴포넌트) | 가볍고 선명함, 상태별 색·움직임 제어 쉬움 |
| AI 실행 | **Claude Pro 구독 + Claude Code CLI** (헤드리스 `claude -p`) · 선택: Claude API | API 요금 없이 구독 사용량으로 실행, 웹 검색 지원 |
| 실시간 표시 | Server-Sent Events(SSE) | 로그·상태를 서버에서 화면으로 스트리밍 |
| 저장소 | JSON 파일 (`data/reports/<id>.json`, git 제외) | 승인된 보고서 저장. 혼자 쓰는 로컬 앱이라 DB 없이 파일로 단순화 (4단계에서 SQLite 계획 변경) |
| 테스트 | Vitest(로직), Playwright(화면) | |

### 4.2 모델 배치 (기본값, 설정으로 변경 가능)

- **최고 등급** (비서실장): `claude-opus-5-5`
- **보통 등급** (실무 직원): `claude-sonnet-5-5`
- **경량 작업** (요약·분류 등): `claude-haiku-5-5`
- AI 공급자는 **Claude 단독**으로 운영 (푸터 표기: "사용 AI: Claude")

### 4.2.1 실제 AI 실행 방식 (3단계 구현, 2026-11-18 구독 방식으로 변경)

| 단계 | 담당 | 모델 · effort | 도구 |
|---|---|---|---|
| 업무 계획 (구조화 출력) | 비서실장 | Opus 5.5 · medium | – |
| 위협정보 조사 | 위협정보 분석가 | Sonnet 5.5 · medium | 웹 검색 최대 5회 |
| 담당 업무 작성 (병렬) | 배정된 1~4명 | Sonnet 5.5 · medium | 컴플라이언스만 웹 검색 최대 3회 |
| 최종 보고서 취합 / 반려 수정 | 비서실장 | Opus 5.5 · medium | – |

- **기본: Claude Pro 구독.** 서버가 로그인된 Claude Code CLI(`claude -p`)를 직원마다 실행합니다. API 요금이 없고 구독 사용량(5시간·주간 한도)에서 차감되며, 업무 로그에 사용률을 표시합니다.
  - 격리 실행: 빈 작업 폴더, 사용자 설정·플러그인·MCP·슬래시 명령 미사용, 도구는 웹 검색만(필요한 직원만), 세션 기록 저장 안 함
  - 환경변수 `ANTHROPIC_API_KEY`가 있어도 CLI에는 넘기지 않아 실수로 API 요금이 발생하지 않습니다.
  - 팀장 본인의 Claude 사용(웹·앱·Claude Code)과 같은 한도를 공유합니다. 실측: 지시 1건(위협정보+1명) 약 3분, 5시간 사용률 약 +5~7%p
- (선택) `AI_BACKEND=api` + `ANTHROPIC_API_KEY` 설정 시 Claude API 방식: 거절 대비 fallback, 지시 1건 비용 상한 5,000원(환율 1,400원 기준 추정).
- 담당자 한 명이 실패해도 나머지 초안으로 결재까지 진행합니다. 중지 버튼을 누르면 진행 중인 Claude 호출도 함께 취소됩니다.
- Claude Code에 구독 계정으로 로그인되어 있지 않으면 시뮬레이션 모드만 쓸 수 있습니다 (터미널에서 `claude` 실행 후 로그인).

### 4.2.2 결재·저장 (4단계 구현)

- **승인** → 보고서를 `data/reports/<승인일시-id>.json`에 저장하고 업무 로그에 "보고서를 기록에 저장했습니다"를 남깁니다. (시뮬레이션 보고서도 저장되며 "시뮬레이션" 표시가 붙습니다.)
- **보고서 기록** (헤더 오른쪽 버튼, 저장 건수 표시) → 최신순 목록 → 보고서 보기 → **HTML 다운로드** / 삭제(한 번 더 확인)
- **HTML 파일**: 스타일이 문서 안에 들어 있어 인터넷 없이 열리고, 인쇄(PDF 저장)용 스타일 포함. 머리말에 팀명·승인 일시·수정 차수·원래 지시, 꼬리말에 "AI 작성·팀장 승인, 확인 필요" 문구. 파일명: `YYYY-MM-DD_보고서제목.html`
- API: `GET/POST /api/reports`, `GET/DELETE /api/reports/[id]` (id 형식 검증으로 경로 조작 차단)

### 4.2.3 시스템 점검(포트 스캔) — 팀장 승인 절차 (2026-11-18 승인)

**절차**
1. 팀장이 점검을 지시 → 비서실장이 **허용 목록의 대상 이름**과 스캔 종류·이유를 정해 **"시스템 점검 승인 요청"**을 올림
2. 팀장이 결재함에서 대상(실제 주소는 화면에만 표시)·스캔 종류·이유를 보고 **[스캔 승인] / [스캔 안 함]**
3. 승인 시에만 **앱(코드)이 nmap 실행** — AI는 옵션·대상을 직접 정할 수 없음
4. 결과를 **별칭으로 바꿔** 취약점 점검 담당이 분석 → 비서실장 취합 → 보고서 결재
5. (옵션) **nmap XML 결과 파일 첨부** 시: 스캔 없이 분석만 (승인 단계 없음)

**안전장치**
| 항목 | 내용 |
|---|---|
| 허용 목록 | `config/scan-targets.json` (팀장만 수정, git 제외). IPv4·호스트 이름·/24 이하 대역만. `-`로 시작하거나 nmap 범위 표기(`1-50`, `*`, `,`)는 거부 |
| 스캔 종류 | 주요 포트 100개 확인 / 서비스 버전 확인 2가지만. 모두 관리자 권한 불필요한 TCP 연결 스캔(`-sT`), 스크립트·OS 탐지 없음 |
| 속도·시간 | `-T3 --max-rate 50 --host-timeout 5m`, 전체 20분 제한, 동시에 1건만, 셸을 거치지 않고 실행(execFile) |
| 승인 대기 | 15분 안에 결정 없으면 미승인 처리, 중지 시 취소 |
| 감사 기록 | `data/audit/scan-log.jsonl` — 요청·승인·거절·취소·완료·실패·첨부 분석 |
| 개인정보·내부정보 | AI에게는 별칭만 전달(원본 XML·실제 IP·호스트 이름 미전송). 팀장 지시문 속 IP도 별칭으로 치환. 별칭↔실제 주소 대응표는 **이 PC에서만** 보고서 부록으로 붙임 |

### 4.3 시스템 구조

```
[브라우저]
```

## 7. 확정 사항 (2026-11-18 팀장 승인)

1. **팀 이름:** AI 정보보안팀
2. **사용자 호칭:** "대표" 대신 **"팀장"** (팀장실, 팀장 지시, 팀장님 확인 필요)

4. **사용 범위:** 팀장 개인 PC 로컬 전용 → 로그인·외부 배포 없음, `localhost`에서만 실행
5. **직원 구성:** 6명 유지, 정보보안팀 역할로 재편 (2.2 참고). 침해대응 담당은 보통 등급
6. **삭제된 요소:** 헤더 예시 칩 A·B, 결재 패널 "FormPilot로 보내기"
7. **조직 배경:** 금융회사 정보보안팀. 컴플라이언스 담당은 전자금융거래법·개인정보 보호법·신용정보법 숙지
8. **시스템 점검:** 팀장 승인 후 앱이 nmap 실행, nmap 결과 파일 첨부 분석 지원, 이 PC에서 점검 대상에 접근 가능 (2026-11-18)
